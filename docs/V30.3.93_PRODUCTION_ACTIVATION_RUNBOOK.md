# v30.3.93 Production Activation Runbook

## Hard gates

1. Confirm project name `Dye Ledger` and expected project reference out of band. Never print credentials.
2. Obtain a production backup and record exact counts for all catalog and Shared Match tables.
3. Validate the migration twice on an explicitly configured disposable Supabase environment.
4. Run allow/deny policy tests for public, anonymous-auth joiner, host, unrelated Account, and catalog maintainer.
5. Confirm Account feature gate remains disabled during schema activation.
6. Apply only the reviewed v30.3.93 migration in one transaction; do not replay historical migrations.
7. Compare postflight counts and foreign-key integrity to the recorded baseline.
8. Perform Course Catalog read and two-device Shared Match smoke tests.
9. Add the Product Owner Account to `course_library_roles` through a privileged administrative path.
10. Enable the Account feature gate only after all prior gates pass and Product Owner separately approves activation.

## Rollback

The rollback restores emergency legacy grants without deleting rows or dropping additive columns. It intentionally does not claim to restore a secure state. If activation fails, disable the Account feature gate, execute the reviewed access rollback, verify local scoring and Shared Match compatibility, and investigate in a disposable environment.
